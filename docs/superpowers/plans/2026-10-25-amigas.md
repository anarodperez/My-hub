# Amigas Implementation Plan

Goal: compartir disponibilidad, planes y regalos dentro de grupos privados existentes, sustituyendo la interfaz de suscripciones.
Architecture: tablas dedicadas con RLS; métodos del repositorio existente; pantalla de grupo con tres secciones, componentes y fotos actuales.
Tech Stack: Expo SDK 54, React Native, Expo Router, Supabase; ninguna dependencia nueva.
Spec: ../specs/2026-10-25-amigas-design.md

## Constraints
Conservar cambios previos y datos de suscripciones. No compartir calendario personal. Toda lectura requiere pertenencia actual al grupo. Identidad y grupo de publicaciones inmutables. Confirmar retirada. No anunciar persistencia si falla.

## Review focus
Cambio de cuenta/ruta durante cargas; expulsión de miembros; respuestas duplicadas; fotos ajenas; pérdida de conexión durante guardado.

- [x] Backend: migración 007 con disponibilidad, publicaciones, respuestas y fotos; prueba SQL con miembros y terceros, revocación y validación.
- [x] Repositorio: tipos y métodos de lectura paginada, publicación, respuesta y retirada; pruebas node con cliente simulado para validación, errores e identidad.
- [x] Interfaz: pestaña Amigas, acceso desde grupo y calendario, espacio compartido y formulario; retirada de accesos de suscripciones, conservación de persistencia antigua.
- [x] Verificación: node --test tests/*.test.cjs, npx expo lint y npx tsc --noEmit; documentar estado de migración y límites comprobados.

Ejecución en esta sesión autorizada por «pues adelante». Sin commits ni cambios remotos destructivos.

## Evidencia
87 pruebas Node pasan; lint y TypeScript sin errores. Siete archivos de pruebas SQL pasan en PostgreSQL 17 aislado, con fixtures revertidos. Migración 007 aplicada al Supabase configurado, después de comprobar proyecto y migración 006; sin datos de prueba remotos. Compilación web generada. Interacción visual y con dos móviles pendiente.

Decisiones: disponibilidad separada del calendario personal; refresco al enfocar o pulsar Actualizar; bucket separado de imágenes para evitar ampliar permisos de fotos personales. No se ofrece borrado de archivos de grupo ni limpieza automática de subidas abandonadas. Un reintento de publicación usa el mismo ID y verifica el contenido antes de recuperar una fila existente.
